## Design

- Triggers: `pull_request` (all target branches) and `push` to `main`. Top-level `permissions: contents: read`; no secrets used.
- One job, `tests`, named `tests (${{ matrix.python-version }})`, so the checks appear as `tests (3.9)`, `tests (3.11)` and `tests (3.14)`. `runs-on: ubuntu-latest`; matrix Python `"3.9"`, `"3.11"`, `"3.14"` (quoted, so YAML does not read them as numbers); `fail-fast: false`.
- Steps: `actions/checkout@v7`, `actions/setup-python@v7` with the matrix version, then `python -m unittest discover -s tests -v` and nothing else. No dependency installation and no cache: the suite is standard library only.
- Action versions [V] (checked 2026-10-22 with `gh release list` / `gh api …/git/ref/tags/…`): `actions/checkout` latest release `v7.0.1` (2026-07-20), tag `v7` = `3d3c42e5aac5ba805825da76410c181273ba90b1` = `v7.0.1`; `actions/setup-python` latest release `v7.1.0` (2026-10-22 02:56 UTC), tag `v7` = `6d4fd22b20465ccc0f7354476588e8df7c9ca0e0` = `v7.1.0`.
- Pinning [D]: the repository has no workflow or pinning convention yet, so the workflow uses the major tags to stay minimal and receive fixes. Full-SHA pinning (with Dependabot for updates) is a possible later hardening step.
- Python availability [V] (`actions/python-versions` `versions-manifest.json`, fetched 2026-10-22): newest stable builds are 3.9.25, 3.11.17 and 3.14.9, each with `linux` / `24.04` / `x64` files. `ubuntu-latest` is Ubuntu 24.04 per the `actions/runner-images` README as fetched 2026-10-22.

## Coverage/data/license/performance limitations

- [U] Linux libm: the sRGB and Rec.709 ulp bounds in the tests (ENCODE/DECODE 5/7 and 3/5) were measured on macOS arm64 libm with zero headroom, and the test docstrings say another libm may need re-measuring. The suite has not run on glibc. A failure on CI from these bounds would be a real portability finding to re-measure, not a reason to loosen the bounds in this task.
- [I] Python 3.9 on future runners: the manifest has 3.9.25 for Ubuntu 22.04 and 24.04 but not 26.04, while 3.11 and 3.14 have 26.04 builds. When `ubuntu-latest` moves to 26.04, `tests (3.9)` would fail at setup. Options then: pin `runs-on: ubuntu-24.04`, or drop 3.9.
- CI interpreters (3.9.25, 3.11.17, 3.14.9) are newer patch releases than the local ones (3.9.6, 3.11.16, 3.14.7).
