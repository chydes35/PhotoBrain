## Design

- Triggers: `pull_request` (all target branches) and `push` to `main`. Top-level `permissions: contents: read`; no secrets used.
- One job, `tests`, named `tests (${{ matrix.python-version }})`, so the checks appear as `tests (3.9)`, `tests (3.11)` and `tests (3.14)`. Matrix Python `"3.9"`, `"3.11"`, `"3.14"` (quoted, so YAML does not read them as numbers); `fail-fast: false`.
- Runner [D]: `runs-on: ubuntu-24.04`, pinned instead of `ubuntu-latest`. [V] [actions/runner-images#14748](https://github.com/actions/runner-images/issues/14748) ("`ubuntu-latest` label will use Ubuntu 26.04 in November 2026", open, read with `gh api repos/actions/runner-images/issues/14748` on 2026-10-22) says the rollout starts 2026-10-19 and should finish by 2026-11-19. [V] The `actions/python-versions` `versions-manifest.json` (fetched 2026-10-22) has Python 3.9.25 for Ubuntu 22.04 and 24.04 but none for 26.04, so `tests (3.9)` would fail at setup on a 26.04 runner. 3.9 stays in the matrix. Dropping 3.9 or moving the runner to 26.04 is a later decision.
- Steps: `actions/checkout` with `persist-credentials: false` (the job never pushes, so the token is not left in the local Git config), `actions/setup-python` with the matrix version, then `python -m unittest discover -s tests -v` and nothing else. No dependency installation and no cache: the suite is standard library only.
- Action versions [V] (checked 2026-10-22 with `gh release list -R <repo>` and `gh api repos/<repo>/git/ref/tags/<tag>`): `actions/checkout` latest release `v7.0.1` (2026-07-20); tag `v7.0.1` and tag `v7` both point to commit `3d3c42e5aac5ba805825da76410c181273ba90b1`. `actions/setup-python` latest release `v7.1.0` (2026-10-22 02:56 UTC); tag `v7.1.0` and tag `v7` both point to commit `6d4fd22b20465ccc0f7354476588e8df7c9ca0e0`. Both refs are lightweight tags of type `commit`.
- Pinning [D]: both actions are pinned to those full commit SHAs with a `# vX.Y.Z` comment. Updates are manual. Dependabot (`github-actions` ecosystem) to propose SHA bumps is a possible follow-up; it is not added here.
- `.gitignore` tooling exception [D]: AGENTS.md:27 says the root `.gitignore` allowlists knowledge folders and adding another root requires a deliberate review. `/.github/` is allowlisted as a reviewed tooling exception for CI workflows, not as a knowledge root, and the file's header comment says so. The allowlist is `!/.github/`, `/.github/*`, `!/.github/workflows/`, so only `.github/workflows/` is trackable; other `.github/` files (for example `CODEOWNERS`) stay ignored. Skeptic's review of this task is that deliberate review.
- Python patch versions [I]: with `check-latest` at its default `false` (setup-python `action.yml` at `6d4fd22`), setup-python uses a matching version already in the runner's tool cache before consulting the manifest. The Ubuntu 24.04 image README (image `20261012.334.1`, read 2026-10-22) lists cached Python 3.11.17 and 3.14.8 and no 3.9, so CI will probably use 3.11.17, 3.14.8 and a downloaded 3.9.25. The manifest's newest 3.14 (3.14.9) is probably not what CI runs. Confirm from the job logs.

- Local tests (`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v`, macOS arm64): see the latest results under "Resolution and rerun evidence".
- YAML: PyYAML is not installed for any local interpreter and `actionlint` is not installed (`brew list`); nothing was installed locally. The file was parsed with the Ruby 2.6.10 standard-library YAML parser (preinstalled with macOS) and gave the intended structure. Skeptic ran `actionlint` 1.7.12 on the workflow: 0 errors. Its built-in action data stops at `actions/checkout` v6, so it did not check the inputs of the v7 actions.
- ulp headroom on glibc: Skeptic measured the tests' bounds on glibc 2.41 over the 300,001-point grid plus 100,000 random inputs. Max ulp error / bound: sRGB encode 5/5, sRGB decode 7/7, Rec.709 encode 3/3, Rec.709 inverse 4/5. CI should pass, but three of the four bounds have zero margin. The suite's own 1001-point grid, max ulp error / bound: sRGB encode 3/5, sRGB decode 6/7, Rec.709 encode 3/3, Rec.709 inverse 3/5. [I] The Ubuntu 24.04 runner's glibc 2.39 is expected to behave the same; not measured. A CI failure from these bounds would be a portability finding to re-measure, not a reason to loosen the bounds in this task.
